# Recovery Card — 다양한 파일 복구를 위한 다음 공개 버전

## 목적과 사용자 요구

사용자는 macOS와 Fujifilm X-T5를 사용하며 사진·영상뿐 아니라 여러 종류의 파일을 강력하게 복구하는 것을 최우선으로 요청했다. GitHub 공개를 제안했다. 현재 앱은 JPEG·RAF의 연속 바이트 추출만 지원한다. 다음 버전은 지원 형식을 넓히고 복구 결과를 검증 가능하게 만든다.

## 제안하는 첫 공개 범위

1. **다중 형식 심층 복구:** 별도로 설치한 PhotoRec 7.2를 앱에서 실행한다. 엔진의 기본 활성 형식을 사용한다. 사진·RAW·영상·음원·문서·압축파일을 포괄하되, 설치된 엔진이 지원하는 범위임을 표시한다. 모든 형식을 강제로 켜면 빈 영역을 dovecot 파일로 오인하는 문제가 합성 테스트에서 확인되었으므로 무조건 전체 활성화하지 않는다. 현재 자체 JPEG·RAF 모드는 유지한다.
2. **안전한 이미지 입력:** 이번 공개 버전은 완성된 평면 디스크 이미지에서만 실행한다. 실제 카드의 복제와 관리자 인증은 현재 별도 작업이며 제품에 통합되었다고 표시하지 않는다. 일반 파일·경로·크기를 확인하고, 원본 변경을 검사한다. 원본에 쓰거나 파일시스템을 수리하지 않는다.
3. **작업과 저장:** 시작 전에 이미지와 출력 폴더를 선택한다. 별도의 새 세션 폴더에 엔진 로그, 작업 설정, 결과, 보고서를 저장한다. 기존 결과를 덮어쓰지 않는다. 공간 부족을 시작 전과 실행 중 확인한다. 외장 SSD 사용을 지원한다. 이미지 복제본과 출력이 같은 SSD에 있는 경우는 허용한다.
4. **진행 상황과 중단:** 엔진 상태, 경과 시간, 현재 발견한 파일 수와 저장 용량을 표시한다. PhotoRec에서 확실하게 얻지 못하는 전체 진행률은 임의로 만들지 않는다. 취소·오류·불완전 종료를 성공으로 표시하지 않는다. 중단된 파일과 로그를 남긴다. 최초 버전은 자동 재개를 약속하지 않는다.
5. **결과 품질과 보고서:** 완료 후 종류별 파일 목록과 크기, SHA-256, 중복 그룹, 검증 상태를 기록한다. JPEG는 실제 디코딩, 영상은 설치된 ffprobe가 있을 때 컨테이너/스트림 확인을 한다. 이 확인은 전체 프레임 디코딩과 구별한다. RAW·그 외 형식은 미검증을 명시한다. 파일명이나 확장자만으로 정상 복구라고 판정하지 않는다. 중복 파일은 삭제하지 않는다. 강력한 복구를 우선한다는 요청에 맞춰, PhotoRec의 손상 파일 보존 옵션을 켜고 해당 파일은 ‘부분 복구·손상 의심’으로 구분한다. 검증된 결과 수에 섞지 않는다.
6. **GitHub 준비:** 한국어·영문 개요, 설치·빌드 안내, 지원/한계 표, 재현 가능한 합성 테스트, macOS CI, 외부 엔진 출처와 라이선스 안내를 포함한다. 실제 SD 이미지·사진·개인 경로·장치 식별자·복구 로그는 공개하지 않는다. 저장소 이름과 공개 라이선스는 게시 직전 확정한다.

## 구현 판단 (사용자가 지정한 사항과 구분)

- 기존 SwiftUI + Rust 구조를 유지한다. PhotoRec는 별도 프로세스로 사용하고 바이너리를 번들하지 않는다. 관리자 권한 없이 이미지 파일을 읽는다.
- 자동 설치 대신 엔진 감지와 설치 안내를 제공한다. 셸 문자열 조합 없이 인자 배열로 실행한다. 작업 디렉터리는 세션 폴더로 고정해 엔진의 부수 파일도 그곳에 남긴다.
- 전체 이미지의 512바이트 경계를 기본 탐색 단위로 사용한다. 일반적인 다양한 형식을 켜두면 다른 파일의 경계를 찾는 데도 유리하다. PhotoRec 사용자 설정의 영향 여부를 검사하고 활성 형식을 기록한다. 파일형식 선택은 추후 필요에 따라 추가한다.
- 결과 경로의 심볼릭 링크·경로 탈출을 거부한다. 보고서에는 상대 경로를 사용한다. 손상된 파일은 자동 실행하지 않는다.
- 입력의 크기·파일 식별정보·변경 시간을 검사한다. 이것을 원본 카드와의 암호학적 동일성 증명이라고 부르지 않는다.
- 기존 JPEG 검증의 크기 한도를 유지한다. 큰 이미지·RAW는 미검증으로 남긴다. ffprobe 실패·시간 초과를 정상으로 처리하지 않는다.

## 검증과 완료 기준

- 합성 디스크에서 JPEG, PNG, ZIP, PDF, MOV/MP4 등 대표 형식이 실제 추출되는지 확인한다. 생성 가능한 형식으로 구성하고, 결과 해시·디코딩 여부를 비교한다.
- 실제 128GB 카드의 복제본에 PhotoRec를 적용하고 자체 엔진 결과와 비교한다. 원래 삭제된 파일의 정답 집합이 없으므로 파일 수를 복구율로 표현하지 않는다.
- 엔진 없음, 공백·한글 경로, 프로세스 실패/취소, 출력 공간 부족, 입력 변경, 악성 결과 경로, 중복 파일을 검사한다.
- 기존 Rust/Swift 검사와 앱 빌드가 통과하고, 앱에서 선택→복구→결과 확인 흐름을 직접 확인한다.
- 공개하는 코드와 테스트만으로 작업을 재현할 수 있어야 한다. 실제 사용자 데이터를 CI에 사용하지 않는다.

## 이후 별도 단계

파일시스템 메타데이터 기반 이름/폴더 복원, ddrescue 복제·재개 UI, LibRaw를 통한 실제 RAF 전체 디코딩, 동일 카메라의 정상 영상을 이용한 untrunc 수리, 단편화된 영상 재조립. 이들은 서로 다른 문제이며 이번 버전의 완료 기능으로 광고하지 않는다. 덮어쓴 데이터와 암호화된 내용의 복구는 보장할 수 없다.

## 공식 근거

- [PhotoRec](https://www.cgsecurity.org/wiki/PhotoRec): GPL v2+, 읽기 전용 접근, 다양한 파일 형식.
- [PhotoRec 사용 문서](https://www.cgsecurity.org/testdisk_doc/photorec.html): 파일명/폴더 한계, 형식 선택과 파일 경계, 중단된 작업.
- [스크립트 실행](https://www.cgsecurity.org/testdisk_doc/scripted_run.html): 인자와 명령, 로그·출력 디렉터리 지정.

상태: 사용자 요구를 반영한 구현 전 설계. 독립 검토에서 제기된 손상 파일 보존 범위는 위의 명시적 분류로 반영했다. 새 기능 구현과 공개 여부는 검토 후 확정한다.
