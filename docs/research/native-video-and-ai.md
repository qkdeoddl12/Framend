# Framend: native recovery and AI research notes

Research checked 2026-10-17. Framend = Frame + Mend. This is an independent implementation, not a claim of a new scientific algorithm or proven superiority over existing tools.

## Implemented foundation

- Rust exFAT parser uses validated directory metadata, FAT chains and bitmap state to recover MOV/MP4 byte extents. Deleted metadata is evidence of a possible file, not proof that no overwrite occurred.
- Rust H.264/HEVC parser reads a healthy reference's codec configuration, identifies plausible length-prefixed NAL chains, starts at IDR pictures, and writes retained payloads to Annex B. Unsupported syntax is rejected. It does not decode or generate missing pixels.
- Standard FFmpeg muxes the elementary stream and independently decodes all audio/video tracks in resulting containers. Frame hashes, diagnostics, source fingerprints and retained byte extents stay in the output session.
- NAL salvage is always partial video-only recovery. Audio and original timing are not recovered. Reference average frame rate supplies estimated timing. A decodable result is not proof of original completeness or correct association of every fragment.
- Metadata-free arbitrary fragment reordering and an AI model are not implemented in this version.

## Primary sources and implications

1. [Garfinkel, Carving Contiguous and Fragmented Files with Object Validation, DFRWS 2007](https://dfrws.org/presentation/carving-contiguous-and-fragmented-files-with-object-validation/). Layer cheap structural checks before expensive object validation. Applied as bounded parsing followed by full decoding; no exhaustive gap-carving implementation is claimed.
2. [Casey and Zoun, Design tradeoffs for developing fragmented video carving tools, DFRWS 2014](https://dfrws.org/sites/default/files/session-files/2014_USA_paper-design_tradeoffs_for_developing_fragmented_video_carving_tools.pdf). False fragment associations and playable-but-incomplete outputs remain material limitations. Preserve provenance and distinguish partial recovery from verified byte identity.
3. [Na et al., Frame-Based Recovery of Corrupted Video Files Using Video Codec Specifications](https://pubmed.ncbi.nlm.nih.gov/24235253/). Relevant prior art for codec-level frame recovery. Do not claim frame-level recovery itself as original invention.
4. [Microsoft exFAT specification](https://learn.microsoft.com/en-us/windows/win32/fileio/exfat-specification). Authoritative basis for boot regions, checksums, allocation bitmap, file entry sets and FAT traversal.
5. [Apple QuickTime chunk offset atom](https://developer.apple.com/documentation/quicktime-file-format/chunk_offset_atom), [FFmpeg documentation](https://ffmpeg.org/ffmpeg.html). Container offsets and decoder behavior must be distinguished from underlying filesystem extents.

## AI direction — proposal, not a shipped feature

The useful first model is a local fragment classifier/ranker. It proposes candidate associations; deterministic syntax checks and independent decoding retain the final say. Never silently substitute generated bytes for recovered evidence.

- [Ghaleb et al., File Fragment Classification using Light-Weight Convolutional Neural Networks](https://arxiv.org/abs/2305.00656), 2023 preprint / IEEE Access 2024. Reports 79% classification accuracy on FFT-75 with about 100K parameters. This is file-type classification, not a 79% recovery rate or proof of correct fragment ordering. Compact local inference is plausible but requires our own benchmark.
- [Lee et al., Byte-level generative predictions for forensics multimedia carving](https://arxiv.org/abs/2604.11010), April 2026 / SPIE. Explores byte prediction and fragment matching on BMP data. This is not demonstrated recovery of missing X-T5 HEVC/RAF content. The experiment motivates ranking candidate continuations, not inventing original footage.

### Experiment before integration

1. Build consented/synthetic X-T5-style H.264/HEVC/RAF corpora. Split train/test by entire source clip and recording session; never let fragments of the same clip leak across splits.
2. Produce ground-truth disk layouts and controlled deletion, metadata loss, gaps, interleaving and overwrite. Preserve original hashes and exact fragment offsets.
3. Baseline is the native engine without AI. Compare a simple byte/statistical ranker with a small learned model. Camera configuration and codec structure are features, not proof of provenance.
4. Measure exact recovered byte/frame recall, wrong fragment joins, top-k candidate recall, decode failures, CPU/memory and elapsed time. Classification accuracy alone is inadequate.
5. Reject uncertain associations or present them as separate partial candidates. Do not advertise calibrated confidence percentages until measured on held-out data.
6. Add local inference only if it improves recovery at an acceptable false-join rate. No media upload or external AI service is required by this proposal.

Generative visual repair, if ever offered, must be an explicitly separate derivative with a record of synthesized regions. It cannot establish the original photographed scene after the source bytes have been overwritten.
